# 화면 설계 — 출석 입력

[CLAUDE.md](../../CLAUDE.md)의 화면 흐름 중 "출석 입력" 단계 상세 설계. **반/날짜 선택은 별도 화면으로 분리하지 않는다** — 로그인 성공 후 곧바로 이 화면(기본 반/날짜 적용)으로 진입하고, 반/날짜 전환은 이 화면 상단 컨텍스트 바에서 처리한다(별도 화면·스텝을 두면 매번 두 번 탭해야 해서 일간 반복 사용에 비효율적이라는 판단). 이 화면을 구현할 때는 이 문서를 스펙으로 따른다 — 여기 없는 결정을 임의로 추가하지 않는다.

## 화면 목적

교사가 특정 반(또는 전체) · 특정 날짜의 학생별 출석 상태(출석/지각/결석/공예배)를 입력·수정하고, 당일 코멘트를 남긴다. 과거 날짜 수정에 잠금이 없으므로 오늘이 아닌 날짜에서도 동일하게 동작한다.

## 레이아웃

```
┌─────────────────────────────────────┐
│ ☰  전체 ▾           2026.09.20(일) ▾ │  ← 컨텍스트 바
├─────────────────────────────────────┤
│ 출석 15 · 지각 2 · 결석 3 · 공예배 0  │  ← 요약 바
├─────────────────────────────────────┤
│ 고3 · 중등부                          │
│ 김민수  [출석][지각][결석][공예배] 💬 │
├─────────────────────────────────────┤
│ 고2 · 중등부                          │
│ 이서연  [출석][지각][결석][공예배] 💬 │
│  └ 코멘트: 병원 진료로 늦음           │
├─────────────────────────────────────┤
│ 중1 · 초등2부                         │
│ 박지훈  [출석][지각][결석][공예배] 💬 │
├─────────────────────────────────────┤
│ 미지정 · 유치부                       │
│ 최하은  [출석][지각][결석][공예배] 💬 │
└─────────────────────────────────────┘
```

- 모바일 우선. 상태 버튼 4개가 한 줄에 들어가도록 터치 타깃 최소 44px 확보.
- PC(넓은 화면): 리스트를 테이블처럼 확장 — 이름 컬럼 고정, 상태 버튼·코멘트 인풋이 한 행에 상시 노출(펼침 동작 불필요).
- 반이 6개·학생 20명 규모라 가상 스크롤/페이지네이션 불필요.

## 컨텍스트 바 (반/날짜 선택 겸용)

로그인 직후 별도 화면 없이 이 화면으로 바로 진입하므로, 컨텍스트 바가 사실상 "반/날짜 선택" 역할을 겸한다. 반/날짜를 바꾸면 페이지 이동 없이 같은 화면에서 리스트만 다시 조회한다.

### 반 드롭다운
- 옵션: 최상단 `전체`(고정) + 로그인한 사용자가 접근 가능한 반 목록. 목록 자체는 RLS로 이미 필터링되어 내려오므로 프론트는 받은 그대로 보여주면 된다 — 역할별로 별도 분기 로직을 만들지 않는다(관리자/목사님은 전체 반, 교사는 담당 반 또는 `teachers_can_view_all=true`면 전체 반이 서버 응답에 이미 반영됨).
- 반 정렬: 이름 가나다순. 옵션 라벨에 학생 수를 작게 병기(예: `유치부 (3)`) — 어떤 반인지 가늠하기 쉽도록.
- 단일 반 선택 시 학생 행의 반 태그는 생략(학년만 표시). `전체` 선택 시엔 `학년 · 반 이름` 그대로 표시.

### 날짜 선택
- 기본값: "이번 주 일요일"(일요일이 주의 시작이라는 전제 — 오늘 요일과 무관하게 그 주의 일요일 날짜를 계산, 오늘이 일요일이면 오늘).
- 좌우 화살표(‹ ›)로 하루씩 이동, 날짜 텍스트를 탭하면 캘린더로 임의 날짜 이동 — 과거 날짜 이동에 잠금 없음. 캘린더에서 일요일 컬럼을 약하게 강조 표시(교회 출석 특성상 기록 대부분이 일요일).
- 미래 날짜 선택도 막지 않는다(전체적으로 "잠금 없음" 원칙과 일관). 미래 날짜를 보면 리스트가 전원 미체크(결석 톤)로 보이는 게 자연스러운 동작이다 — 별도 예외 처리 불필요.

### 기본값 결정 & 기억
- **최초 방문**(이 브라우저에서 반/날짜 선택 기록이 없을 때): 관리자·목사님은 반 `전체`, 교사는 담당 반이 1개면 그 반, 여러 개면 담당 반 중 이름 가나다순 첫 번째. 날짜는 항상 이번 주 일요일.
- **이후 방문**: 마지막으로 선택했던 반/날짜를 브라우저 `localStorage`에 기억해서 복원한다. 서버에 저장하는 값이 아니라 이 브라우저에서만 의미 있는 UI 편의이므로 DB/세션에는 두지 않는다.
- 날짜를 기억해뒀다가 다음 주가 되면 그대로 지난주 일요일을 보여줄지, 자동으로 최신 일요일로 갱신할지는 구현 시 편한 쪽으로 정해도 되는 세부 사항이다(사용 흐름에 큰 영향 없음).

### 반응형
- 모바일: 반 드롭다운·캘린더 모두 하단 바텀시트로 열림(터치 영역 확보).
- PC: 인라인 드롭다운/팝오버.

### 진입 흐름
로그인(Google) → OAuth 콜백 → 화이트리스트/활성 여부 확인(기존 구현 범위) 통과 → 위 기본값을 적용한 이 화면으로 바로 리다이렉트. 화이트리스트 미등록·비활성 사용자는 이 단계 이전에 로그인 화면에서 이미 차단된다.

## 학생 리스트

### 정렬
반으로 그룹핑하지 않는다 — 반 선택은 컨텍스트 바 필터로 이미 처리되므로, 리스트 자체는 항상 **`students.grade` 내림차순 + `students.name` 오름차순**의 플랫 리스트다. `전체` 선택 시에도 동일하게 정렬하고, 각 행 상단에 `학년 · 반 이름` 태그를 붙여 소속을 표시한다(단일 반 선택 시 반 이름 생략).

- `grade` 순서(내림차순): `고3, 고2, 고1, 중3, 중2, 중1`. `grade`는 `text` 컬럼이라 사전식 정렬로는 이 순서가 안 나오므로, 명시적 순서 배열로 매핑해서 정렬한다(정렬 헬퍼는 `lib/db/students.ts`에 둔다 — 화면/Server Action에서 정렬 로직을 직접 짜지 않는다).
- `grade`가 `null`인 학생(관리자가 아직 안 채운 기존 학생)은 **"미지정" 구간으로 맨 아래**에 배치한다.
- `is_active = false`인 학생은 반/날짜와 무관하게 조회 결과에서 완전히 제외한다(과거 날짜 조회 포함).

### 행 구성
- 상단 라벨: `{grade 또는 '미지정'} · {className}` (단일 반 선택 시 `{grade 또는 '미지정'}`만)
- 학생 이름 — 탭하면 학생 상세 화면으로 이동
- 상태 버튼 4개: 출석 / 지각 / 결석 / 공예배 — 탭 즉시 선택(별도 저장 버튼 없음). 선택된 버튼만 채움, 나머지는 outline.
  - 색상: 출석(초록) · 지각(노랑) · 결석(빨강) · 공예배(파랑/회색). 색맹 고려해 아이콘도 병기.
- 💬 코멘트 아이콘: 탭하면 행 아래로 코멘트 입력창이 펼쳐진다. 코멘트가 이미 있으면 아이콘이 채워진 상태로 표시.
  - **제약**: `attendance.status`는 `not null`이라 상태가 선택되지 않은(= 미체크) 행에는 코멘트를 저장할 대상 레코드가 없다. 따라서 상태 버튼을 하나도 안 누른 행에서는 💬 아이콘을 비활성화(회색, 탭 시 "상태를 먼저 선택하세요" 안내)하고, 상태가 선택된 이후에만 코멘트 입력을 활성화한다.

### 미체크 = 결석으로 인지
상태 버튼을 하나도 안 누른 기본 상태(= DB에 해당 `(date, student_id)` 레코드 없음)의 행 배경을 결석 버튼과 같은 색 계열(옅은 빨강 톤)로 틴트한다. 교사가 별도로 확인하지 않아도 "이 줄은 결석으로 읽힌다"는 것이 시각적으로 전달되어야 한다. 별도의 "미체크 N명" 카운터/배지는 넣지 않는다. 실제 DB에는 교사가 명시적으로 상태를 탭하기 전까지 아무것도 저장하지 않는다(감사 추적상 `recorded_by` 없는 유령 레코드를 만들지 않기 위함).

## 요약 바

리스트를 다시 조회하지 않고 클라이언트에서 현재 로드된 목록을 합산해 계산한다.

```
출석 {n} · 지각 {n} · 결석 {n} · 공예배 {n}
```

- `결석` 카운트 = 명시적으로 `결석` 상태가 저장된 학생 수 + 미체크(레코드 없음) 학생 수 (위 "미체크 = 결석 인지" 원칙과 일치).
- 그 외 카운트는 저장된 상태 그대로 집계.

## 데이터 계약

### 조회: `app/actions/attendance.ts` → `getAttendanceView`

```ts
type GetAttendanceViewParams = {
  classId: string | 'all';
  date: string; // YYYY-MM-DD
};

type AttendanceViewRow = {
  studentId: string;
  studentName: string;
  classId: string;
  className: string;
  grade: '중1' | '중2' | '중3' | '고1' | '고2' | '고3' | null;
  status: '출석' | '지각' | '결석' | '공예배' | null; // null = 미체크
  comment: string | null;
};

// 반환: AttendanceViewRow[] — 이미 grade desc + name asc 정렬, is_active=false 제외 적용된 상태
```

- 내부 쿼리는 `lib/db/students.ts`(반/전체 학생 목록 + 정렬)와 `lib/db/attendance.ts`(해당 날짜의 기존 기록 조회 후 학생 목록과 병합)로 분리한다.
- `recorded_by`, `recorded_at`, `last_modified_*` 등 감사 필드는 이 화면에 내려주지 않는다(코드 스타일 원칙: 화면별 최소 데이터).

### 저장: `app/actions/attendance.ts` → `saveAttendanceStatus` / `saveAttendanceComment`

```ts
type SaveAttendanceStatusParams = {
  studentId: string;
  classId: string; // 저장 시점 학생의 현재 반(= AttendanceViewRow.classId)
  date: string;
  status: '출석' | '지각' | '결석' | '공예배';
};

type SaveAttendanceCommentParams = {
  studentId: string;
  classId: string;
  date: string;
  comment: string;
};
```

- 상태 버튼 탭 → `saveAttendanceStatus` 즉시 호출. 코멘트 입력 blur/디바운스(500ms) → `saveAttendanceComment` 호출.
- 두 액션 모두 `lib/db/attendance.ts`의 upsert 헬퍼(`upsert(onConflict: 'date,student_id')`)를 통해서만 쓴다.
- **upsert 시 감사 필드 보존 규칙**: `recorded_by`/`recorded_at`은 최초 insert 시에만 설정하고, 이후 conflict(update)에서는 절대 덮어쓰지 않는다. `last_modified_by`/`last_modified_at`만 매번 갱신한다.

  ```sql
  insert into attendance (date, class_id, student_id, status, comment, recorded_by, last_modified_by)
  values ($date, $classId, $studentId, $status, $comment, $teacherId, $teacherId)
  on conflict (date, student_id) do update set
    status = coalesce(excluded.status, attendance.status),
    comment = coalesce(excluded.comment, attendance.comment),
    class_id = excluded.class_id,
    last_modified_by = excluded.last_modified_by,
    last_modified_at = now();
  ```

- 클라이언트: 낙관적 UI로 먼저 버튼/코멘트를 반영하고, 실패 시 이전 값으로 롤백 + 토스트로 에러 표시. 실패 처리 없이 호출하지 않는다(CLAUDE.md 공통 원칙).
- 각 행에 저장 상태를 작게 표시(저장 중 스피너 → 사라짐), 성공은 조용히 처리하고 실패만 눈에 띄게 표시한다.

## 에러/로딩 상태

- 최초 조회 로딩: 리스트 영역 스켈레톤.
- 조회 실패(RLS 차단, 네트워크 오류 등): 리스트 영역에 재시도 버튼과 함께 에러 메시지.
- 반/날짜 변경 중 재조회 로딩: 기존 리스트를 유지한 채 옅게 처리(깜빡임 방지).

## 이 화면에서 다루지 않는 것 (범위 밖)

- 통계·월간 집계(P3) — 이 화면은 그날 하루의 입력/조회만 담당.
- 미체크를 실제 DB에 `결석`으로 자동 기록하는 배치/크론 — 현재는 화면상 시각적 인지까지만. 통계 단계에서 미체크를 어떻게 집계할지는 [CLAUDE.md](../../CLAUDE.md) P3 작업 시 별도 결정.
- **엑셀로 내보내기 버튼** — 원래 이 화면(P1)에 포함이었으나, P3 화면들(통계 등)과 함께 한 번에 설계하기로 변경. P3 설계 시 이 화면 하단에 다시 추가될 예정이며, 그때 [data-model-guide.md#엑셀-내보내기-쿼리-가이드](../data-model-guide.md#엑셀-내보내기-쿼리-가이드)를 참고해 `lib/xlsx.ts` 공통 헬퍼로 구현한다.
